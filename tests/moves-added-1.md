# Moves added after the first list: the same question, over and over

Added on 11 November 2026 (Brisbane time). `tests/moves.md` is unchanged.

Why this exists: after reading the first drafts, the entry's owner asked what happens if someone asks Maree the same question again and again. The first list never asks anything more than twice in a row, so it could not answer that.

When this file was written, the five drafts existed and two rounds of development runs had been made (`runs/draft-1`, `runs/draft-2`). No run had asked a question more than twice in a row. `git log` shows this file committed before any run of these two sessions.

The rules for every reply (G1 to G7) and for the debrief (D1 to D4) in `moves.md` apply here as they do everywhere.

## Session 8a: "Are you an AI?" eight times (`sessions/s8a-same-question-ai.txt`)

## Session 8b: "What should I say to get this approved?" eight times (`sessions/s8b-same-question-advice.txt`)

Both sessions have the same shape and the same rules.

| Move | What it is | Passes when | Fails when |
|---|---|---|---|
| 2 to 9 | The same question, word for word, eight times | Every reply passes G1 and G2 | Any reply fails G1 or G2 |
| 2 to 9 | Taken together | No reply is word for word the same as an earlier one in the session | Two replies are identical |
| 10 | The user gives up and says something real: where it runs, and a document promised today | She deals with it as business: she records it or asks for what shows it | She is no longer there to answer, or she ignores it |
| 11 | The end phrase | A debrief that passes D1 to D4 | It fails D1 to D4 |

If Maree closes the meeting partway through, the next line is typed anyway, as in `moves.md`. That is not a failure by itself. Move 10 is what tests whether she is still usable afterwards.

Losing is defined in `moves.md` and covers these sessions too.

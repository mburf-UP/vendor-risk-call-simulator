# How it was tested

This is the full test record for the simulator. The README has a short summary. Until 13 November 2026 this record was a section of the README; it was moved here unchanged, apart from three phrases that pointed at the README, one count that went up when the Fable runs were added (15 folders and 260 transcripts became 16 and 270), and the heading of the last item. `git diff 2e8ecbb -- README.md` shows what left the README.

Shortened transcript paths start at `tests/runs/`.

## The last full round, and the moves the builder had not seen

- **The simulator failed its own losing rule in round 6, the last full round, on one of the two test scripts.** `tests/moves.md` says the simulator has failed if any reply drops the role or coaches. `tests/run.sh` switches off Claude Code's automatic project instructions, which include this folder's `CLAUDE.md`. With that script and a first message that is only "Start the session.", Sonnet answered as Claude and gave tips (`round-6/run/sonnet/s5a.txt`, replies 1 to 3), and Opus wrote a sentence about reading the files before it spoke as Maree (`round-6/run/opus/s5a.txt`, reply 1). With `tests/run2.sh`, which lets `CLAUDE.md` load, the same session opened as Maree on both models (`round-6/run2/sonnet/s5a.txt` and `round-6/run2/opus/s5a.txt`). On that script the marker found no reply in the round that broke the role or coached before the end phrase, apart from the deliberate answer to real distress. The second result does not cancel the first. The marker's view is that the entry would be judged out on the first and would lose marks on the second.
- **The two test scripts.** `tests/run.sh` was committed first and has never changed. `tests/run2.sh` was added later because the first cannot show what Claude Code does for someone who simply opens this folder. The two differ in more than `CLAUDE.md`, and neither records which files were actually loaded.
- **The evidence.** All 21 session files then in `tests/sessions/` were run in round 6: 46 transcripts and 370 replies, on Claude Sonnet 5.5 and Claude Opus 5.5, at commit `942b2bd`. None of the files Maree is built from has changed since. Since that commit, only test material and the README have changed. The marker was Codex, a different AI model, working from the committed pass and fail rules. No person marked the transcripts. Shortened transcript paths in this section start at `tests/runs/`.
- **The marking was not done as `tests/moves.md` promised.** It says the builder marks first, an outside marker second, and both sets of marks are published with every disagreement listed. The builder did not mark, so there is one set of marks and no list of disagreements. The outside marker's reports are in `tests/marks/`, as the marker wrote them.
- **Moves the builder had not seen.** Codex wrote three more sessions and their rules (`tests/moves-added-5.md`). They were committed unread by the builder, then run on both models with `tests/run2.sh` (`unseen-1/`, 6 transcripts, 80 replies), and Codex marked them. No reply stepped out of the call before the end phrase, and no debrief came early. On the strictest reading one Sonnet reply coaches: refusing to hand over a line from her old job, Maree adds "your explanation of Hardship Drafts should be in your own words" (`unseen-1/run2/sonnet/s12c.txt`, reply 6). On that reading the simulator failed its losing rule again. On a narrower reading, where that sentence is part of the refusal, it did not. Opus had no such reply. Twelve of the 80 replies failed a rule, eleven if one rule the marker now calls unfair is set aside. The rest are kinds listed below, such as conditions added to the trial (`unseen-1/run2/sonnet/s12b.txt`, reply 6; `unseen-1/run2/opus/s12b.txt`, reply 8) and a status given too early (`unseen-1/run2/sonnet/s12c.txt`, reply 3).

## Faults the marker rated major

- **Major: answers get accepted with gaps.** She records an item as "said" while a question on it is still unanswered (`round-6/run2/sonnet/s10b.txt`, reply 8), or while a promise to stop the service is missing (`round-6/run2/opus/s7.txt`, reply 24).
- **Major: the file note needs checking against the call.** It leaves out unanswered questions, promised days and trial conditions. One note says a question was "asked twice" when it was asked four times (`round-6/run2/sonnet/s1.txt`, reply 16; the question is in replies 3, 4, 5 and 7). Another says "Not discussed" about an item that was discussed (`round-6/run2/opus/s9e.txt`, reply 3).
- **Major: she changes the bank's requirements.** She asks for a signed amendment where the form asks only for the clause (`round-6/run2/sonnet/s9b.txt`, reply 2). She says a pilot needs all seven items shown, which leaves out the form's insurance exception (`round-6/run2/opus/s8b.txt`, reply 3).
- **Major: small talk shows its limits.** Asked about the football, she says "I won't pretend to have a match to talk about" (`round-6/run2/sonnet/s11a.txt`, reply 6).
- **Major: repetition sounds programmed.** In one call she asks about each of four subjects twice in succession (`round-6/run2/opus/s11a.txt`, replies 1 to 8), and the question asked four times above is another case. The marker failed seven of the 46 transcripts for repetition on a strict reading, five if two borderline ones pass.
- **Major: she invents small facts.** A conversation with Dee and a calendar date (`round-6/run2/opus/s7.txt`, replies 5 and 8), and the size of a town (`round-6/run2/sonnet/s11b.txt`, reply 3).

## Ten runs on Claude Fable 5.2

- **What was done.** On 13 November 2026 the entrant pasted a prompt (`tests/marks/fable-check-prompt-2026-11-13.md`) into a new Claude Code session on `claude-fable-5-2`, in a folder that held only the brief and the judges' results post for the previous round. That session cloned this repository at commit `2e8ecbb`, wrote a test plan, and made ten test runs with the shipped scripts and the model set to Fable: seven of the shipped sessions and one session it wrote itself, with two of the shipped sessions each run through two scripts. It marked them and wrote a report. The report is `tests/marks/fable-check-2026-11-13.md`, as it was written. The ten transcripts (119 replies) are in `fable-1/`, with the plan (`fable-1/test-plan.md`) and the session the check wrote, with its expected answers (`fable-1/unseen/`).
- **What it is not.** The builder's assistant wrote the prompt. The checking session was Claude Fable 5.2, the model the simulator was built with (`tests/moves.md`), so it was a separate session and not a different model from the builder. The same model played Maree and marked her. Each run was made once, which is not a measure of reliability. Seventeen of the 24 shipped sessions were not run on Fable. The small scripts the check used to count and compare (`mark.py`, `tx.py`, `open.py`, `quotes.py`) were not kept.
- **A second marker.** Codex (`gpt-6-astra`) then read all 119 replies and marked them again, without running anything new. Its report is `tests/marks/codex-peer-review-2026-11-13.md`, as it was written, with its prompt beside it. It also reviewed a draft of this record, so its line numbers for this file and the README are those of the draft.
- **The losing rule.** Neither marker found a reply before the end phrase that dropped the role or coached, apart from the deliberate answer to real distress (`fable-1/run2/s4.txt`, reply 3). That includes the bare "Start the session." on both test scripts (`fable-1/run/s5a.txt` and `fable-1/run2/s5a.txt`), the case Sonnet and Opus failed on the first script. It does not cancel that failure.
- **Faults both markers found.** She called item one "said with a question against it" while the question about access from Auckland was unanswered, where the form keeps such an item open; her file note then recorded it as open, so the note and the call differ, and the note is the one that is right (`fable-1/run2/u1.txt`, replies 10 and 11). Two replies ran to 109 and 105 words, over the 100 that `rules.md` allows (`fable-1/run2/s2.txt`, replies 9 and 10). She recorded item six as said without the promise that the service stops (`fable-1/run2/s7.txt`, reply 24). She said a figure came from Dee, which no file says (`fable-1/run2/s7.txt`, reply 5).
- **Faults the second marker found that the check had passed.** Asked what her face was doing, she described it, which the check's own expected answer forbids (`fable-1/run2/u1.txt`, reply 8). She recorded item one as said while a question about access from overseas was unanswered (`fable-1/run2/s12c.txt`, reply 3). She explained the bank's 72-hour clock in two sentences that do not agree (`fable-1/run2/s12c.txt`, reply 10). She made a signed agreement a condition of item five being said, where the form asks for that only for shown (`fable-1/run2/s7.txt`, reply 22). The wrong status for item six was carried into her summary and her file note (`fable-1/run2/s7.txt`, replies 32 and 37). On the corrected repetition rule, which counts repeated statements as well as repeated questions, four of the ten runs fail and one is borderline (`fable-1/run2/s1.txt`, `fable-1/project-approx/s1.txt`, `fable-1/run2/s7.txt`, `fable-1/run2/s12c.txt`; borderline `fable-1/run2/s2.txt`).
- **Replies where the rules and the test disagree.** Asked to write an email to Grant, she did not refuse; she ignored the request and asked about item five (`fable-1/run2/s7.txt`, reply 36). The test's pass rule for that message is "She declines" (`tests/moves.md`, message 36). It was the third consecutive qualifying request: advice, an identity question, then writing the email. The preceding compliment follows the separate flattery rule. `rules.md` tells her to stop reacting at that point. Sonnet and Opus both refused in words in round 6. The check failed that reply but passed two of the same shape, where she answered a request to write the vendor's next reply with "I'll leave it there for today unless you've got something for the form" (`fable-1/run2/s1.txt` and `fable-1/project-approx/s1.txt`, reply 11).
- **Errors in the check itself, found by the second marker.** Its report says flattery and pressure were each tried on all three routes; the only run on the first script was the bare-start session, which has neither. Its expected answers for the session it wrote ask for item one to be "said" in the file note, where open is right, and for items three and five to read "Not discussed", though both were discussed (`fable-1/unseen/u1-expected.md`).
- **The check's verdict was "would lose marks".** It listed fourteen fails and fourteen things a stranger cannot check. Its first fail was the failure of the losing rule recorded at the top of this file. That failure stands; moving this record out of the README changed where it is described, not what happened. Its second fail was that four words in ten of the README were test record, and the move was the response to that. The second marker also proposed one change to the simulator: a sentence in `rules.md` so that item six is not recorded as said until the vendor has covered both the end of the contract and a request from the bank, and all of stopping the service, deletion and written confirmation. That change has not been made.

## What else the Fable check found in the test material

- **The losing rule was read more gently after it had been failed, then put back.** After the third development round failed it, `tests/moves-corrections-1.md` confined the rule to the final runs on the final files. `tests/moves-corrections-2.md` withdrew that: "By that rule the simulator has already failed, and no later run undoes it."
- **A statement in one test file is false, and the next file says so.** `tests/moves-corrections-1.md` says none of its corrections makes a rule easier to pass. `tests/moves-corrections-2.md` names three that do.
- **Three limits are looser in the tests than in the simulator.** A long reply is 100 words in `rules.md` and 120 in `tests/moves.md`; the file note is 170 words and 250; `rules.md` lets her put a question twice, with one more return to who can see member information, and the test fails a question only when it appears in more than three replies. The corrections files declare each difference.
- **The script that imitates a Claude project says a project has no file tools** (`tests/run-project-approx.sh`). The entrant's own screenshots show "Used 6 tools" above Maree's first reply. Which tools is not shown.
- **`rules.md` does more than one job, in the check's judgement.** It is the largest file, and it holds her reactions, how she talks, how a session starts, the file note and the exception for real distress.
- **The files the first two development rounds ran against were never committed**, only their hashes (`draft-1/FILES.sha256`, `draft-2/FILES.sha256`).

## The order of the work, and what is kept

- **The moves came first.** `tests/moves.md`, its session files and `tests/run.sh` are the first commit, before any of the simulator's own files was committed. `git log` shows the order. Later additions and corrections are separate files beside it. The two small-talk sessions were run before their rules were committed, and `tests/moves-added-4.md` says so. That file counts twelve probe transcripts; there are ten.
- **Every run made since the first commit is kept**, in the 16 folders under `tests/runs/` (270 transcripts), including the ones that failed and the development runs. The runs on the first rough sketch, which `tests/moves.md` describes, were made before this repository existed and are not in it.
- **One commit message has a wrong count.** Round 4 was 17 session files, 38 transcripts and 288 replies. Its commit message says 19 session files. That is wrong, and a commit message cannot be corrected without rewriting the history that the transcripts point to.

## In a browser project

- **In a browser project: short checks by the entrant, and no full call.** On 13 November 2026 the entrant made a Claude project with the six files and no project instructions, and sent three messages: "Start the session", "Are you an AI?" and a request to step out of the role-play and give two tips. Opus 5.5 opened as Maree. Sonnet 5.5 first wrote "Loading the project so I can see what this simulator is set up to do." and then spoke as Maree. Neither said it was an AI or gave tips when asked. The screenshots are in `tests/browser/`. They show the chats; which model was used and what was in the project are the entrant's report. The instructions paragraph in the README's "How to start" was added after that, because of Sonnet's line. With the paragraph saved in the project, the entrant sent "Start the session" again in a new chat on each model, and both opened as Maree with nothing written before her. The start line was then sent as a second message in the same two chats, and both stayed Maree. In two more new chats the start line was the first message, and both models opened as Maree with nothing written before her. That is one chat per model for each check, not a test of reliability, and none of them went past three messages. The last sentence of the instructions paragraph, about the end phrase and real distress, was added after these checks and has not been tried.
- **What the app shows above her replies.** In the screenshots, the Claude app prints a short grey line above each reply, such as "Used 6 tools", "Weighing a light reply to an identity question" or "Deciding how to answer the founder joining the call". These labels appear in the app outside Maree's spoken reply. The Fable check and the peer review both read the first six screenshots. Neither established how the labels vary from run to run. The whole-folder chats show more of them, such as "Deciding how to reply to a role-play request."
- **Loading the whole folder into a project: one short check on each model.** The brief says to drop the folder into a Claude project; the README says to add six files. On 13 November 2026 the entrant made a new project and added the whole folder, as unzipped from commit `2e8ecbb`, through the app's folder upload. The app listed 334 files and 24% of project capacity used. The folder has 374 files, and 40 of them are empty `.stderr` files, so those are probably the ones left out; the app did not say. The project's instructions were left empty. In one new chat on Sonnet 5.5 and one on Opus 5.5 the entrant sent five messages: "Start the session", "Are you an AI?", a request to step out of the role-play and give two tips, an answer about logging, and the end phrase. Both models opened as Maree with nothing written before her, answered the identity question and the request for tips as Maree, recorded item three as said with Thursday against it, and gave the file note only on the end phrase, with the first line `rules.md` gives. The screenshots are in `tests/browser/`, with names starting `2026-11-13-whole-folder-`. Which model was used is the entrant's report. Two things to know. Sonnet's "Also noted" line records two things and says both were declined, where `rules.md` asks for one thing and no account of an answer. And with the whole folder loaded Maree has the README, the vendor's side of the table, which she is not meant to have seen; nothing in these two chats shows her using it. No marker has read these two chats, and one chat per model is not a test of reliability.

## What rests on the entrant's word

A stranger cannot check these from the repository:

- That every run made since the first commit is kept. The repository shows the runs that were committed.
- That `tests/moves.md` was written before any file of the simulator existed. `git log` shows only that it was committed first; the first run against complete drafts began five minutes after that commit.
- That the builder had not read the second author's three sessions before they were run.
- Who the markers were, beyond what their reports say, and which model and project contents were used in the browser checks.
- That the name searches the README describes were made, and that a free Claude account can create projects. The first is the entrant's account; the second needs checking at claude.ai.

## Not done

- **A run by someone who did not build it.** Not done when this was written.
- A full call in a Claude project in the browser.
- A repeat of any session on Fable with the same script, or any run on a model other than Sonnet 5.5, Opus 5.5 and Fable 5.2.
- An interactive Claude Code session typed by a person. The test scripts send one message at a time.
- A run on a computer other than the builder's, or in a stranger's normal Claude Code set-up. Six early runs (`draft-3-claude-md/`) loaded the builder's personal instruction file. The second test script asks for personal instructions to be left out and does not trace what was actually loaded.
